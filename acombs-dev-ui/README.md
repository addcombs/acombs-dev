# acombs-dev

Standalone Angular 21 and Angular Material 21 frontend with responsive navigation,
adjustable brightness, and a technology dashboard, open to everyone without signing in.
The toolbar uses the theme surface color with primary-colored text and icons,
over a decorative inline SVG pixel mosaic (`src/app/theme/toolbar-background.ts`)
filled with the theme's primary and secondary colors, so it follows light/dark mode and brightness. The footer
displays the API's health, polling `/actuator/health` every 5 minutes.
The dashboard cards explain the roles of the included technologies and are
grouped into Front-end, Back-end, Cloud, and Tools tabs, also reachable from the side menu.
Each card opens a page (`src/app/technologies/technology-page.ts`) on what's great about that
technology's latest release, with the version this site runs and a link to the official notes. The
content lives in `src/app/technologies/technologies.ts`, with the date it was last checked
(`CHECKED_ON`). Pages use hash URLs, such as `/#/technologies/angular`, because the static S3 and
CloudFront hosting has no fallback that would serve `index.html` for other paths.
The Material 3 palettes are generated from the single indigo `#3F51B5`, which Material also tones down for the secondary color
(`src/app/theme/generated_theme-colors.scss`, via `ng generate @angular/material:theme-color`).

Card logos are served locally from `public/logos`, from
[Devicon](https://github.com/devicons/devicon) (MIT; see
`public/logos/DEVICON-LICENSE.txt`). Spring Boot, Spring Boot Actuator, and Spring Boot DevTools
share the Spring logo, and Angular-family cards reuse the Angular and Angular Material logos.
Cards with no bundled, permissively licensed logo (SVG, Material Icons & Lato,
Claude, the PowerShell scripts, and the AWS services and tools) show a Material icon instead. Logos remain
trademarks of their owners; their appearance identifies technologies, not
an endorsement.

## Local setup

Requirements: Node.js and npm.

```bash
npm ci
npm start
```

Open `http://localhost:4200/`. The local `/api`, `/actuator/health`,
`/swagger-ui`, and `/v3/api-docs` proxies target `http://localhost:8080` in `proxy.conf.json`
(`src/app/api-url.ts` keeps API paths relative in development and prefixes the API host in production).
The toolbar's ⋮ menu links to the backend's Swagger UI and opens an About dialog.
Without the API running on port 8080 the footer reports it as unreachable; the rest of the app works.
To run both, run `..\scripts\start-all.ps1` in PowerShell: it installs dependencies, builds and
tests both apps, then starts the API on port 8080 and this UI on port 4200 (logs in `..\logs`).

## Brightness

The toolbar shows a sun for the light profile or a moon for the dark profile.
Click the brightness icon in the toolbar to show or hide the horizontal
slider to its left, with an accessible label and no visible text. Opening it
does not change the theme. Slide right for
light surfaces (100%) and left for dark surfaces (0%).
Backgrounds move through neutral grays from `#121212` (dark) to `#FAFAFA` (light),
without a primary-color tint. Surface text uses black or white, whichever provides greater
contrast. Primary buttons, icons, borders, and highlights steadily darken from
tone 80 on the darkest background to tone 40 on the lightest background.
Primary accents can have reduced contrast against backgrounds near the middle
of the slider. Filled primary
controls use contrasting black or white text.
The level is saved locally and restored on reload; without a saved level it starts
from the system's light or dark preference.
Keyboard users can adjust the slider with arrow keys, Home, and End.

## Settings

`src/app/project.settings.ts` is generated by the setup scripts (`Sync-UiConfig` in
`..\scripts\common.ps1`) from `..\project.json`; edit that, not the generated file. It holds the
app's name, the developer's name, and the API's URL. The development proxy does not apply to
production builds: they call the API at its own host (`apiUrl`, e.g. `https://api.acombs-dev.com`),
which allows this app's origin through CORS.

## Build and tests

```bash
npm run build
npm test
```

Build output is written to `dist/`. Unit tests use the Angular CLI and Vitest.
The initial bundle (about 560 kB, 120 kB compressed, mostly Angular and Angular Material)
warns above 1 MB and fails above 1.5 MB. Each component stylesheet warns above 4 kB, so the
toolbar's brightness-slider styles live in `src/app/main/brightness-control.scss`, apart from `app.scss`.
